## 简介
本文件面向 BoscoTsang 用户与运维人员，提供系统化的故障排除与常见问题解答。内容覆盖部署问题、下载失败、认证问题、性能问题、平台兼容性、网络连接、配置错误排查，以及日志分析、错误代码解释与修复步骤。同时给出社区支持渠道与问题反馈流程，帮助快速定位与解决问题。

## 项目结构
BoscoTsang 采用前后端分离架构，后端基于 FastAPI，前端基于 Vue3，通过 Docker Compose 统一编排。核心目录与职责如下：
- backend：后端服务与管理模块
- frontend：Vue3 单页应用
- cli：命令行工具
- extensions：浏览器扩展示例
- releases：发布与诊断文档
- scripts：辅助脚本（版本更新、清理、测试）
- docker-compose.yml / Dockerfile：容器化部署配置
- docs：技术文档与使用手册

## 详细组件分析

### Telegram Bot 诊断与修复
常见症状：Bot 无响应、错误日志为空、无法获取更新。诊断要点包括 Bot Token 配置、网络可达性、SSL 证书、依赖版本与日志级别。

```mermaid
flowchart TD
Start(["开始诊断"]) --> CheckToken["检查 Bot Token 配置"]
CheckToken --> TokenOK{"Token 有效？"}
TokenOK --> |否| FixToken["重新配置 Token 并保存"]
TokenOK --> |是| CheckNet["测试网络访问 api.telegram.org"]
CheckNet --> NetOK{"可访问？"}
NetOK --> |否| ConfigProxy["配置 HTTP/HTTPS 代理"]
NetOK --> |是| CheckSSL["检查 SSL 证书"]
CheckSSL --> SSLOK{"证书正常？"}
SSLOK --> |否| UpdateCert["更新 CA 证书"]
SSLOK --> |是| CheckDep["检查 httpx 版本"]
CheckDep --> DepOK{"版本兼容？"}
DepOK --> |否| UpgradeDep["升级 httpx"]
DepOK --> |是| EnableDebug["提升日志级别为 DEBUG"]
EnableDebug --> TestScript["运行测试脚本 test_telegram.py"]
TestScript --> Result{"测试通过？"}
Result --> |否| ReviewLog["查看详细日志并定位异常"]
Result --> |是| Restart["重启服务验证"]
Restart --> End(["结束"])
ReviewLog --> End
```

### 下载失败排查流程
常见原因：链接无效、Cookies 失效、磁盘空间不足、网络异常、平台限制。建议按顺序检查并修复。

```mermaid
flowchart TD
S(["开始"]) --> CheckLink["确认下载链接有效性"]
CheckLink --> LinkOK{"链接有效？"}
LinkOK --> |否| FixLink["修正或更换链接"]
LinkOK --> |是| CheckCookies["检查平台 Cookies"]
CheckCookies --> CookiesOK{"Cookies 有效？"}
CookiesOK --> |否| RenewCookies["重新导出并上传 Cookies"]
CookiesOK --> |是| CheckDisk["检查磁盘空间"]
CheckDisk --> DiskOK{"空间充足？"}
DiskOK --> |否| CleanDisk["清理旧文件释放空间"]
DiskOK --> |是| CheckNet["检查网络连接"]
CheckNet --> NetOK{"网络正常？"}
NetOK --> |否| ConfigProxy["配置代理或修复网络"]
NetOK --> |是| CheckLogs["查看应用日志"]
CheckLogs --> Analyze["分析错误类型与堆栈"]
Analyze --> Retry["重试下载"]
Retry --> End(["结束"])
```

## 性能考虑
- 并发控制：合理设置下载并发数，避免带宽与磁盘瓶颈
- 存储策略：定期清理缓存与旧文件，保持磁盘空间充足
- 网络优化：在受限网络环境下配置代理，减少超时与失败
- 资源监控：关注 CPU、内存、磁盘 IO 使用情况，必要时扩容

## 故障排除指南

### 通用诊断步骤
- 查看容器状态与日志：确认服务是否正常运行
- 检查持久化卷：确认 downloads、cookies、data、logs 目录存在且可写
- 验证端口映射：确认宿主机端口映射正确且未被占用
- 检查环境变量：核对 APP_BASE_DIR、HTTP_PROXY、HTTPS_PROXY、TZ 等
